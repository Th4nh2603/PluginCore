# Spec: Auth Web

## Objective

Scaffold a functional React login experience for a generated Monorepo. The page lets a user submit Email/Password credentials to `auth-core`, start the later Google OAuth flow, and enter a protected application shell after `/auth/me` confirms identity.

The page serves developers using a repository starter: its single job is to make the current authentication state and available sign-in actions unambiguous.

## Tech Stack

- React 19, Vite 8, TypeScript 5
- Native `fetch`; no auth SDK or client-side token storage
- React Context for authenticated-user state
- CSS modules-free component styles in `src/index.css`

## Commands

From a generated repository root:

```powershell
pnpm dev
pnpm --filter ./apps/web build
pnpm --filter ./apps/web test
```

## Project Structure

```text
apps/web/src/
  auth/api.ts                typed API requests with credentials included
  auth/AuthProvider.tsx      current-user state and login/logout operations
  auth/LoginPage.tsx         Email/Password form and Google entry point
  auth/ProtectedApp.tsx      authenticated shell with logout action
  App.tsx                    provider-aware state switch
  index.css                  page tokens, layout, responsive rules
```

## UI Design

Palette: `Ink #10233F`, `Cobalt #2256D7`, `Signal #54E0B5`, `Mist #F4F7FB`, `Line #C8D4E3`, `Alert #B42318`.

Typography: `IBM Plex Sans` for interface/body; `IBM Plex Mono` for endpoint/status labels. The generated page uses system fallbacks and does not download fonts.

Layout:

```text
┌──────────────────┬──────────────────────────┐
│ PLATFORM ACCESS  │ Sign in                   │
│ API: connected   │ email [                 ] │
│ JWT: HttpOnly    │ password [              ] │
│                  │ [ Continue ]              │
│                  │ ───── or ─────             │
│                  │ [ Continue with Google ]  │
└──────────────────┴──────────────────────────┘
```

The signature element is the left “access status” rail: it explains the live contract (API endpoint, cookie-based credential handling) rather than using decorative illustration. On small screens it becomes a compact header above the form. Reduced-motion users receive no transition animation.

## Code Style

Use a typed request helper and keep token handling server-owned.

```ts
export const getCurrentUser = async (): Promise<User | null> => {
  const response = await fetch(`${apiOrigin}/auth/me`, { credentials: "include" });
  return response.status === 401 ? null : (await response.json()).user;
};
```

Components use plain functions, accessible labels, visible focus styles, and action copy that states the result (`Continue`, `Sign out`). API errors are direct and actionable.

## Testing Strategy

- Generate unit tests for `auth/api.ts` covering `credentials: "include"`, 401 current-user behavior, and generic login error propagation.
- Generate React tests for valid submit loading state, invalid credentials message, Google redirect, and protected-state logout.
- Plugin regression test checks all frontend source and test files are scaffolded and the build succeeds.

## Boundaries

- Always: use `credentials: "include"`; never read/write JWTs in browser storage; label inputs; support keyboard submit; show accessible errors.
- Ask first: add a registration page, password reset, remembered-device feature, third-party UI kit, or client router.
- Never: put OAuth client secrets in Web code; use localStorage/sessionStorage for tokens; claim Google sign-in works before `google-oauth` is implemented.

## Success Criteria

- `apps/web` includes `LoginPage`, `AuthProvider`, API client, protected shell, styles, and test files.
- Email/Password form calls `/auth/login` with credentials included and renders API failure text.
- Google button navigates to `/auth/google` and shows a clear configuration notice until `google-oauth` is scaffolded.
- `/auth/me` controls whether the login form or protected shell is rendered.
- Generated Web app builds successfully.

## Open Questions

None. The Google button routes to the backend endpoint that the later `google-oauth` module will implement.
