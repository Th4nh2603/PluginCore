# Spec: Auth Core

## Objective

Scaffold a secure, runnable Email/Password authentication foundation for newly created Monorepos. A user can register, log in, log out, and retrieve the current authenticated user. The API persists identities in PostgreSQL and sends a 15-minute JWT only in an `HttpOnly` cookie; browser JavaScript never reads the token.

Success means a generated Monorepo includes a Prisma schema, PostgreSQL development service, API routes, auth middleware, environment template, and tests for successful and rejected credential flows.

## Tech Stack

- Node.js 22, TypeScript 5, Express 5, pnpm workspaces
- PostgreSQL 16 via Docker Compose and Prisma
- `argon2` using Argon2id password hashes
- `jose` for signed JWTs
- `helmet`, `express-rate-limit`, and `cookie-parser`
- Vitest for API unit/integration tests

## API Contract

```text
POST /auth/register  { email, password } -> 201 { user }
POST /auth/login     { email, password } -> 200 { user }, Set-Cookie: access_token
POST /auth/logout    -> 204, clears access_token cookie
GET  /auth/me        -> 200 { user } or 401
GET  /health         -> 200 { status: "ok" }
```

Passwords must be 12-128 characters. Authentication failures use the same generic `Invalid email or password` response. The JWT contains only `sub` (user ID), `email`, `iat`, and `exp`; it expires after 15 minutes. Cookie options are `httpOnly: true`, `sameSite: "lax"`, `secure: NODE_ENV === "production"`, and `path: "/"`.

## Data Model

```prisma
model User {
  id           String   @id @default(cuid())
  email        String   @unique
  passwordHash String?
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
}
```

`passwordHash` is nullable to allow the later Google OAuth module to create Google-only accounts. Passwords are never persisted or logged in plaintext.

## Code Style

Use focused functions with validated input and explicit response types.

```ts
export const issueAccessToken = async (user: AuthUser): Promise<string> =>
  new SignJWT({ email: user.email })
    .setSubject(user.id)
    .setIssuedAt()
    .setExpirationTime("15m")
    .sign(jwtSecret);
```

Route handlers delegate password/JWT behavior to `src/auth` helpers. No handler reads a raw environment variable except the central auth configuration module.

## Testing Strategy

- Unit-test password validation, JWT issuance/verification, and cookie options.
- Integration-test register, login, logout, and `/auth/me` with a temporary PostgreSQL database URL supplied by the test environment.
- Verify generic invalid-credential responses, missing/expired JWT rejection, and login rate-limit behavior.
- Run `pnpm test`, `pnpm lint`, `pnpm typecheck`, and `pnpm build` in the plugin repository before committing.

## Boundaries

- Always: validate request bodies; normalize emails; hash passwords with Argon2id; set secure cookie options; keep secrets only in `.env`; test auth failures.
- Ask first: add refresh tokens, password resets, email verification, RBAC, any external identity provider beyond Google, or a cloud database service.
- Never: commit secrets; log passwords/JWTs; store passwords plaintext; expose JWTs to browser JavaScript; weaken rate limiting for production.

## Success Criteria

- A generated Monorepo starts PostgreSQL via `docker compose up -d db`.
- Prisma defines `User` with unique email and nullable password hash.
- Register/login/logout/me routes meet the stated API contract.
- Valid login sets a 15-minute `HttpOnly` cookie; invalid login does not disclose whether an email exists.
- Generated API builds and its auth tests pass once `DATABASE_URL` and `JWT_SECRET` are configured.

## Open Questions

None for `auth-core`. Google OAuth, React UI, and README generation are separate approved modules and do not belong to this spec.
